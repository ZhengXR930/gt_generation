Issue description:
A heap-double-free occurs in the CRAM decoder's name decoding path. On a decode error, `rle_decode()` frees the caller-supplied output buffer, but ownership still belongs to `decode_names()`, which retains the same pointer for later cleanup. This leads to a second free of the same memory during error cleanup.
