Issue description:
A heap-use-after-free occurs in the TLS client when handling a peer's temporary key. After `EVP_PKEY_assign_DH(peer_tmp, dh)` transfers ownership of the DH object to `peer_tmp`, the shared error cleanup still frees the local `dh` alias. This leaves `peer_tmp` holding a dangling pointer, leading to a double-free when `EVP_PKEY_free(peer_tmp)` is called, with the second free writing to the freed object's reference counter.
