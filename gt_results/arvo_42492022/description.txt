Issue description:
An out-of-bounds read occurs in `cram_varint_decode_init` when the `varint_get*` functions read varint data without enforcing the end of the input buffer. A boundary check can also be invalidated in the FQZ decoder because `b->uncomp_size` is not set before `int32_get_blk` uses it.
