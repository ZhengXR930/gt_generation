Issue description:
In Dovecot's SMTP server, the DATA command cleanup logic destroys the global data input stream based solely on reply success or chunk_last, without verifying that the command being destroyed actually owns the stream. This can lead to a heap-use-after-free when a later failed DATA command frees an earlier BDAT command's shared input stream, causing a crash during subsequent reads.
