Issue description:
An out-of-bounds read occurs in DNS packet parsing when an NFLOG TLV length is used without accounting for the required 4-byte alignment between records. In `parseResources`, the next TLV is located from `getSize()`/`getDataLength()` using the unaligned `recordLen` field, so a padded TLV can cause parsing to start inside padding bytes and read past the actual record boundary.
