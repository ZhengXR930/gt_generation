Issue description:
An out-of-bounds read occurs in `bcf_dec_typed_int1_safe()` when decoding a typed integer from a BCF record. The bounds check uses `bcf_type_shift[t]` directly instead of the actual byte width `1 << bcf_type_shift[t]`, so `INT16` and `INT32` values may be read from `p` even when fewer than 2 or 4 bytes remain before `end`.
