Issue description:
A global buffer overflow read occurs in multiline string lexing. In `lex_multiline_string()`, the code compares `lexer->pos` against the closing delimiter with `strncmp(lexer->pos, end, 3)` after checking only that `remaining(lexer) < 3`, but it does not enforce that `lexer->pos` still points within the original input buffer, so `lex_next()` and `parse_key_value()` can cause a 3-byte read past the end of the global input buffer while scanning for the terminator.
