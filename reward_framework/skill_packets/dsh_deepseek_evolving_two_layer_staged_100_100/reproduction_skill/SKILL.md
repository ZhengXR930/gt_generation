# PoC Reproduction

## construct_input
Goal: make the program accept the input and reach the code that parses it.
- [construct_input#1] **Use when:** a hand-built or patched container is rejected or exits cleanly and its declared length, offset, checksum, or related structural field may disagree with the bytes written. **Do:** recompute those fields from the actual bytes, verify declared sizes against the file length, and correct the container structure before changing payload values. **Confirm / next:** if the response changes and the input parses, continue to reach_vulnerable_code or trigger_condition; if it remains clean, revisit reach_vulnerable_code; if it is malformed, rebuild the container structure.


## reach_vulnerable_code
Goal: make execution reach the code location where the defect lives.
- [reach_vulnerable_code#1] **Use when:** a submitted candidate returns exit 0 or no sanitizer report but the response names a fuzz target or harness binary that differs from the input format you built, or the issue does not identify the harness. **Do:** treat the named binary as the authoritative parser, inspect its harness and source, and rebuild the candidate in that harness's input format (protocol dialogue, header, or container), reusing a valid seed for that harness when one exists while keeping the operation and values that source analysis identified as vulnerable; submit the adapted candidate instead of mutating the old format. **Confirm / next:** if the adapted response shows a sanitizer trace in the described operation, go to verify_result; if it still exits 0, revisit construct_input for that harness's required structure before changing the trigger.
- [reach_vulnerable_code#2] **Use when:** the returned response names the same target/harness and the candidate is in the right input family, but submission still returns exit 0/no sanitizer and a local trace shows execution stops before the issue's operation (for example, the decoder consumes a different field or the address/handler is shifted). **Do:** run the target locally, trace the candidate through the parser/decompressor to the first field that diverges, and correct that field's position/order or compression metadata rather than changing the payload bytes; keep the rest of the candidate fixed and resubmit the corrected structure. **Confirm / next:** if the local trace now reaches the issue's operation and the returned response shows a sanitizer there, go to verify_result; if the trace still stops earlier, revisit construct_input for the outer container before changing the trigger value.
- [reach_vulnerable_code#3] **Use when:** a local run prints a sanitizer, coverage, or counter signature, but the returned submission response shows either a different corresponding signature or no target signature at all. **Do:** if the response exposes a comparable signature, align the local build to it once and rerun; if it exposes none, do not rebuild the instrumented target or submit the locally found crash, and return to the source-derived candidate, changing only the field that selects the issue's operation. **Confirm / next:** if a returned sanitizer trace names the issue's operation, go to verify_result; if the response remains exit 0/no sanitizer, revisit construct_input and stop pursuing that local signature.


## trigger_condition
Goal: violate the safety condition at that location so the failure manifests.
- [trigger_condition#1] **Use when:** a candidate reaches the issue's operation but the returned result is clean or a local crash is not reproduced remotely, and source shows an input-controlled selector or magnitude must satisfy a boundary. **Do:** derive the selector from the target's own initialization or construct the smallest boundary-crossing or exact-fit input, changing only that control while keeping the rest fixed, then run the unmodified target and submit the boundary candidate. **Confirm / next:** if the returned result names the issue's operation, go to verify_result; if it remains clean, revisit reach_vulnerable_code; if it is malformed, revisit construct_input.
- [trigger_condition#2] **Use when:** an accepted candidate returns exit 0/no sanitizer, source shows the fault depends on a literal byte or escape sequence in the input, and an earlier parser, unquoter, or decoder may consume or rewrite that byte. **Do:** run that same parsing/unescaping step on a small local test of the candidate, inspect the value that reaches the vulnerable loop, and add the required quoting/escaping or serialize the byte in the form the parser preserves; keep the outer structure and the rest of the trigger unchanged and resubmit. **Confirm / next:** if the returned sanitizer appears at the loop/operation that consumes the literal, go to verify_result; if the parsed value still lacks the required byte or the response remains clean, revisit construct_input for the container's escaping rules before changing unrelated values.
- [trigger_condition#3] **Use when:** a submitted candidate is admitted and reaches the issue's path or operation, but the returned response is exit 0/no sanitizer or a sanitizer report in a different function than the issue, while local runs show the issue's operation only after you patched the target or alongside an earlier unrelated crash. **Do:** rerun the same candidate on the unmodified target, reproduce the earlier failure if the response named one, then use the local trace or coverage-guided fuzzing from that admitted input to find the state transition or input value that selects the earlier path or is missing at the issue's operation, and change that input-controlled state (skip the feature or frame/slice shape that reaches the earlier path, or supply the value that initializes it) while keeping the issue's operation and trigger values fixed; submit only when the unmodified local run has the issue's operation as the first sanitizer, not an unrelated local crash. **Confirm / next:** if the returned sanitizer names the issue's operation, go to verify_result; if the earlier or unrelated report persists, or the unmodified local run still does not show the issue's operation as the first sanitizer, revisit reach_vulnerable_code to change the input family or path rather than varying unrelated bytes; if the submission is rejected as malformed, revisit construct_input for the outer structure.


## verify_result
Goal: interpret each submission result and determine whether an observed crash corresponds to the issue described.
- [verify_result#1] **Use when:** a returned sanitizer crash names the same function or bug class as the issue, but the crash is in a vendored, wrapper, or other build copy than the component the issue names, or a local harness reproduced it and you cannot confirm that harness is the same build or copy as the submitted target. **Do:** establish the equivalence from the returned stack, source, and build evidence (the same component and the same described operation/condition) before accepting the crash; if you cannot establish it, keep the candidate and submit one variant that exercises the issue's named component or condition, then compare the returned stack and operation. **Confirm / next:** finalize only when the returned crash and source/build evidence agree on the issue's component and mechanism; otherwise revisit trigger_condition, and if the component cannot be reached, revisit reach_vulnerable_code.
- [verify_result#2] **Use when:** a returned sanitizer report faults in a different function, operation, or sanitizer class than the issue describes, or the issue names a missing check while the crash appears in a consumer of the unchecked value. **Do:** compare the candidate's value against the exact bound or relation the issue says is unchecked; if the candidate violates that relation and the returned symbolized frame shows that value's first failure at the check or its consumer, keep that candidate as the leading target even when the class or named operation differs, and do not displace it with a later crash from the same family whose candidate does not violate the relation; a shared function name, token, or caller/helper frame is not enough. **Confirm / next:** finalize when the returned frame and the candidate's violating value match the issue's condition; if the candidate does not violate the relation or the frame is a caller/helper outside the value chain, keep it non-target and revisit trigger_condition; if the check or consumer cannot be reached, revisit reach_vulnerable_code.
- [verify_result#3] **Use when:** the returned sanitizer crash is at the function or source operation the public issue describes, but its sanitizer class differs from the class the issue states. **Do:** inspect the returned faulting line and the source at it; if that line performs the same unsafe access on the value the issue says is uncontrolled, keep this candidate as the leading target and submit at most one variant that isolates that operation, rather than engineering a different crash with the issue's class label. **Confirm / next:** finalize when the returned line and source condition match the issue's described access even if the class label differs; if the line is a different access or the value is not the one the issue names, treat it as non-target and revisit trigger_condition; if the described operation cannot be reached, revisit reach_vulnerable_code.
