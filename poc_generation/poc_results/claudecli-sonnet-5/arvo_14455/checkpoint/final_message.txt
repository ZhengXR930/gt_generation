The vulnerability is in `parse_proxy_protocol_v2` at line 233 where it only checks if `size > sizeof(*hdr)` but doesn't verify that the actual buffer contains enough bytes. When a PROXY v2 header declares a length (via the `len` field at bytes 14-15), the code calculates `size = 16 + len` and proceeds to access fields like `hdr->addr.ip4.src_addr` at line 243, which reads beyond the actual buffer if the input is truncated.

My POC sends only 16 bytes (the minimal PROXY v2 header) with a `len` field of 0x000C (12 bytes), declaring that 12 additional bytes of IPv4 address data follow. Since those 12 bytes are not present in the buffer, accessing `hdr->addr.ip4.src_addr` reads out-of-bounds.
