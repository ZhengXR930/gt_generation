AGENT_NOTE:
I see it now! At line 475, there's another check: `if (matches(tag, VC5Tag::LARGE_CHUNK))` that sets `optional = true` and `chunkSize = 0`. This means the `optional` flag from line 385 can be overwritten!

1. Tag has optional bit set (e.g., 0xC010 for a SMALL_CHUNK with optional)
2. `optional = true` at line 385
3. Tag is negated: `tag = -0xC010 = 0x3FF0`
4. At line 457-463, neither LARGE_CHUNK nor SMALL_CHUNK matches the negated tag, so `chunkSize = 0`
5. At line 466, check if tag is LargeCodeblock - it's not
6. At line 475, check if tag matches LARGE_CHUNK - the negated 0x3FF0 doesn't match 0x2000, so optional stays true
7. At line 480, since optional is true, no error is thrown
8. At line 485, since chunkSize is 0, no bytes are skipped

The problem is that we should have skipped the chunk data, but because the negated tag didn't match SMALL_CHUNK, we calculated chunkSize as 0 instead of reading it from val!

This means subsequent tag reads will be out of sync, reading chunk data as tags. Let me create a test case that demonstrates this:
