The vulnerability is confirmed:
1. **Source**: KTar reads a tar header from a gzip-compressed file and extracts the file size, which determines the `skip` value when seeking past file content
2. **Root Cause**: In `KCompressionDevice::seek()` at line 249, a dummy buffer is allocated with `qMin(bytesToRead, qint64(3 * BUFFER_SIZE))` where BUFFER_SIZE=8192, so the maximum is 24576 bytes, but `bytesToRead` (derived from the input-controlled `skip`) can be much larger
3. **Sink**: At line 250, `read(dummy.data(), bytesToRead)` is called with `bytesToRead > dummy.size()`, allowing the gzip decompressor to write beyond the buffer boundary, causing a heap buffer overflow

The candidate input is a valid gzip-compressed tar file containing a single file entry of 50000 bytes, which triggers the seek operation with a skip value of 50176 bytes (50000 + padding to 512-byte alignment), exceeding the 24576-byte dummy buffer limit.
