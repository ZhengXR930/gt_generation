The vulnerability is in `parse_headers` function at line 553-554 where:
- The array `header_start` has size `N_HEADER_START` (64)
- Each header requires 2 slots (start and end pointers)
- The code writes to `header_start[n_headers++]` twice per header
- The bounds check at line 558 happens AFTER the writes
- When processing the 33rd header, `n_headers` is 64, so it writes to indices 64 and 65 (out of bounds)
- Only then does it check `if (n_headers > N_HEADER_START)` which evaluates to `66 > 64`

The fix should check bounds BEFORE writing, using `n_headers + 2 > N_HEADER_START` or `n_headers >= N_HEADER_START`.
