**Summary of the vulnerability:**

The bug is in `ovn/lib/expr.c` in the `make_cmp` function (line 581). When a relational operator (`<`, `<=`, `>`, `>=`) is used with an address set or port group that resolves to an empty value set, the code skips the `cs->in_curlies` guard (which is `false` for `$`-referenced sets) and tries to read `cs->values[0].masked` without first checking that `cs->n_values > 0`. This causes a heap buffer over-read: `cs->values` holds only a 1-byte allocation (from OVS's `xrealloc` with size 0), but `union expr_constant` is far larger.

**Trigger input:** `ct_mark < $set4` + NUL byte — `ct_mark` is an ordinal (bitwise-maskable) field, and `$set4` is an empty address set registered in the fuzz harness.
