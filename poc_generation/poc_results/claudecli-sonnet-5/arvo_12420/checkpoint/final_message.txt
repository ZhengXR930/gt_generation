The vulnerability triggered on the first submission. `triggered: true` confirms the buffer overflow in `idn2_to_ascii_4i()` was reproduced.

The candidate was256 bytes: the64-character domain `aaa.bbb.ccc.ddd.eee.fff.ggg.hhh.iii.jjj.kkk.lll.mmm.nnn.ooo.pppp` encoded as little-endian uint32_t values. When `idn2_lookup_u8()` returns that64-byte ASCII domain, the subsequent `strcpy(output, output_u8)` at line 621 writes 65 bytes (64 chars + NUL) into a caller-provided buffer expected to hold at most 64 bytes, triggering the overflow.

The `analysis.json` on disk captures the full causal path:
- **source** (line 581): `input` array enters `idn2_to_ascii_4i`
- **intermediate** (line 611): `idn2_lookup_u8` returns up to 255 bytes with no label-length cap
- **root_cause** (line 614): missing check `strlen(output_u8) <= IDN2_LABEL_MAX_LENGTH` before copy
- **sink** (line 621): `strcpy(output, output_u8)` overflows the 64-byte output buffer
