## Analysis

I identified the vulnerability in `common/convert.cpp` in the `DecodeDirect` template class:

**Over-read bug (lines 553-555)**: When processing UCS-2 or UCS-4 input with an explicit size, the code calculates the stop pointer by adding the byte size to `in0` and then casting to `Chr*`. If the size is not a multiple of `sizeof(Chr)`, the loop can read 1-3 bytes past the buffer boundary.

**Null-termination bug (lines 549-551)**: When `size == -1`, the code uses `*in` to check for null termination, which only checks the first byte. For UCS-2/UCS-4, this incorrectly identifies characters with a zero first byte as null terminators.
