Based on my analysis of the source code, I've identified the buffer overflow vulnerability in the `parse_tables` function at lines 2027-2029 where the RLE decompression writes past the `bit_length[HUFF_BC]` array without proper bounds checking. 

The vulnerability occurs when:
1. Input-controlled nibble values are extracted from compressed Huffman table data
2. An escape code (value 15) is encountered
3. The next nibble specifies an RLE count
4. The loop writes `value + 2` zeros without checking if `w + value + 2` exceeds `HUFF_BC` (20)
5. This causes writes past the end of the 20-byte `bit_length` array
