The benchmark confirms `triggered: true`. The candidate input successfully triggered the uninitialized memory read in the SGI RLE image parser.

The vulnerability path:
1. `_starttab = new quint32[_numrows]` (line 334) — allocates uninitialized memory
2. `for (l = 0; !_stream.atEnd() && l < _numrows; l++)` (line 335) — exits early when file ends, leaving entries `l.._numrows-1` uninitialized
3. `if (_starttab[o] + _lengthtab[o] > (uint)_data.size())` (line 350) — sanity check reads all `_numrows` entries including the uninitialized ones

The 524-byte SGI file provides a valid 512-byte header (RLE=1, 2×2 RGB, `_numrows=6`) followed by only 3 of the required 6 start-table entries, causing the stream to end early and leaving `_starttab[3..5]` and all `_lengthtab[0..5]` entries uninitialized when the sanity check runs.
